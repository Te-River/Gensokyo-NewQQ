## 四、逻辑问题汇总清单（交用户决定）

以下问题按优先级排列，**均未修复**，由用户决定是否处理及处理方式。

### P1 - 高优先级

#### 4.1 handlers 热路径无聚焦测试（F1 延续）

- **现象**：send_group_msg.go（3074 行、83 commits）与 message_parser.go（2540 行、71 commits）为最高 churn 文件，无直接测试
- **影响**：任何行为变更无回归保护，统一管道重构的正确性仅靠手动验证
- **建议**：参照 retry_policy_test.go 模式，为 parseMessageContent 的 foundItems 解析路径与 send_group_msg 的错误分类/重试分支添加聚焦测试

#### 4.2 CI 无测试门禁（F2 延续）

- **现象**：cross_compile.yml 在 PR 触发时仅编译，不运行 go test / go vet
- **影响**：AGENTS.md 要求的「PR 需附测试通过证据」无机械执行
- **建议**：在 PR 触发路径添加 `go test ./...` 与 `go vet ./...` 步骤

### P2 - 中优先级

#### 4.3 前端测试为占位符（F3 延续）

- **现象**：frontend/package.json 的 test 脚本为 `echo "No test specified" && exit 0`
- **影响**：前端 16 个 TS/JS 源文件无任何测试文件，变更无回归保护
- **建议**：用真实测试框架替换占位脚本，或移除该脚本并明确前端无自动测试

#### 4.4 SSM 补发无关联标识（F4 延续）

- **现象**：`echo.PushGlobalStack(pair)` 与 `SendStackMessages()` 的日志无队列级关联标识
- **影响**：诊断「补发是否触发/消费」只能靠 groupID/messageID 人工关联
- **建议**：在入队与补发路径记录共享关联标识（如 queue_id 或 correlation_id）

### P3 - 低优先级

#### 4.5 [CQ:face] 文档与实现不一致

- **现象**：CQ 码汇总.md 与 face 子文档已标注"开发中"，但代码中仍无 face 解析逻辑
- **影响**：下游插件按文档使用 `[CQ:face]` 将得到原文未解析的结果
- **状态**：已在文档中标注，无需进一步处理（等待官方开放接口）

#### 4.6 MCP 依赖未固定版本

- **现象**：.mcp.json 中 context7 和 github 两个 MCP 以 npx 运行未 pin 版本
- **影响**：每次启动拉取最新包，运行时行为可能漂移
- **建议**：在 .mcp.json 中为两个 MCP 服务指定明确版本
